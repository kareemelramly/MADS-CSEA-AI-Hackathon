# Design decisions

The choices behind the system, with the alternative we rejected and why. Each one traces to our architecture decision record (ADR) numbering.

| # | Decision | Rejected alternative | Why |
|---|---|---|---|
| ADR-01 | A fixed Python state machine runs the six phases; agents are role functions with one prompt and one JSON schema each | An LLM "manager" agent or a swarm that decides what to do next | Every transition is explicit and testable offline; a gate cannot be skipped by model wording. A complete run is designed for about 15–16 model calls; this is a design estimate, not an observed full-run measurement. |
| ADR-02 | A single-use approval executor gates business effects | A boolean "approved" flag in the UI | A changed page, price or recipient after approval is refused and logged with the changed field |
| ADR-03 | Work is bounded per segment: 1 search broadening, 1 repair per call, 4 attempts per call, 3 builds, 2 demand experiments, at most one pivot per gate | Open-ended retries | A segment ends at a founder pause or its time limit. A run may remain paused while waiting for the founder. |
| ADR-04 | SQLite is the source of truth; `decision_log.json` is exported atomically from it | Appending to JSON directly | Crash-safe log, approvals and mock ledger |
| ADR-05 | No agent framework | LangGraph, CrewAI, AutoGen | The approval executor and gates would still be custom; plain Python keeps the code small and auditable |
| ADR-06 | Code owns every business and safety decision; checks run in the order hard rules → data completeness → locked thresholds → founder | Asking the model "should we continue?" | The model proposes text; numbers and outcomes come from code with thresholds logged before data |
| ADR-07 | Rules first, model second: deterministic guardrails on every generated text and every request; for typed requests a local-model rule check runs after the patterns and can only add refusals, never remove one | A model as the only safety gate; patterns only | Patterns are reproducible but missed 9 of 12 held-out paraphrases; a model generalises better but can be wrong, so it never overrules a pattern refusal and never lifts an approval |
| ADR-08 | Missing data is never a negative verdict: thin search → `repeat`, unrun experiment → `awaiting_evidence`, model outage → `repeat` | Treating zero sign-ups from an unrun test as failure | Honest results; the system says "stop" only after evidence was really examined |
| — | Source registry: the model sees source IDs and excerpts, code renders the URLs | Letting the model write links | Invented links become impossible; unsourced claims print as ASSUMPTION |
| — | Product scope A1 (checklist pack) built from a team template; model fills text only | Model-generated code or HTML | Fourteen deterministic checks can prove the product works without running generated code |
| — | Local model only (llama.cpp): Qwen3 4B Instruct 2507 by default on CPU, Gemma 4 26B A4B on a GPU | A hosted API tier (an NVIDIA-hosted Gemma tier was built, then removed) | The hosted tier timed out on almost every request in testing and would send founder content off the machine. Local-only means no key, no account, $0.00 model charges and no data leaving except search words; hardware and electricity are excluded (ASSUMPTION). |
| — | Small default model for `docker compose up`, large model behind the GPU override | Gemma 26B (about 17 GB) as the default for everyone | Anyone without a GPU can run the whole system on a laptop CPU; the larger model stays one flag away |
| — | Evidence hygiene in code: duplicates count once, only request, complaint and workaround count as demand, a target country no source mentions is ASSUMPTION | Counting every relevant-looking link | An outside review found duplicate excerpts and product launches inflating the evidence count, and an "Egypt" segment no source supported |
| — | Guardrails: a question is educational only when it contains no instruction to produce something | Skipping all checks for any text that starts with "what", "how" or "should" | "What is a countdown timer? Add one" passed the old bypass |
| — | Every run ends with a report built from the log (Markdown and HTML in `outputs/`, PDF in the app) | Leaving the founder to read 30 separate files | One readable result per run; nothing in it is typed by hand |
