## 2. What the system is

A team of open-source agents takes a founder brief through six gated phases:

1. Discover
2. Validate
3. Build
4. Commercial setup
5. Launch
6. Operate and learn

Design rules:
- Code decides every gate (go / repeat / pivot_back / stop / awaiting_evidence), checked in this order: hard rules → completeness → thresholds → founder.
- A single-use approval executor binds each approval to the action, content SHA-256, destination, amount (always 0) and run ID.
- Payments are a MOCKED SQLite ledger: pay → deliver → refund → revoke → reconcile. Publishing and sending are STUBBED. Personas are SIMULATED.
- The model sees source IDs (S001…); code turns them into URLs. An unsourced claim is labelled ASSUMPTION.
- `decision_log.json` is exported from SQLite.
- The UI is Streamlit (`app.py`): a dark editorial design where agents run in a background thread.
- There is also a CLI: `python -m orchestrator --brief tests/fixtures/brief_r.json --label r`.
